MediSUS · contexto02 / 08

01 · problema público

Condições de armazenamento também importam

A disponibilidade de um medicamento não é a única questão: suas condições de armazenamento precisam ser acompanhadas.

Desafio

Perceber e registrar variações

Sem um registro contínuo, uma alteração de temperatura pode passar despercebida entre verificações.

Contribuição

Apoiar a observação

Um fluxo de monitoramento pode registrar leituras e destacar valores fora de uma faixa definida para o cenário.

Conexão com CitizenTech: aplicar tecnologia a um desafio de serviço público, com foco na saúde e no apoio à gestão.
Fala sugerida: “A proposta se conecta ao MediSUS pelo contexto da saúde pública. O recorte IoT trata das condições de armazenamento e da possibilidade de registrar variações para apoiar a observação pela equipe.”

02 · o que foi desenvolvido

Da leitura ao registro de alerta

O serviço recebe uma mensagem, valida os dados, aplica uma regra configurada e persiste o resultado.

Na demonstração

Um simulador publica quatro leituras sintéticas: 4,5 °C, 5,2 °C, 8,3 °C e 3,8 °C.

Parâmetros do exemplo

Os limites 2 °C e 8 °C servem somente para demonstrar a regra de alerta.

O ESP32 e o DS18B20 estão representados em um firmware de referência. As leituras apresentadas são simuladas; não houve validação em hardware.
Fala sugerida: “Na execução, o simulador substitui o sensor físico. O monitor valida cada mensagem, compara a temperatura com os limites de demonstração e grava a leitura e o status no SQLite.”

MediSUS · código05 / 08

04 · onde olhar no VS Code

Cada arquivo tem uma responsabilidade

  • docker-compose.yml
    Broker, monitor, simulador e armazenamento.
  • src/medisus_iot/simulator.py
    Publica os valores sintéticos.
  • src/medisus_iot/monitor.py
    Assina o tópico MQTT e coordena o processamento.
  • src/medisus_iot/readings.py
    Valida mensagens e aplica a regra de limites.
  • src/medisus_iot/storage.py
    Grava e consulta leituras no SQLite.
  • tests/
    Testa validação, limites, persistência e IA simulada.
  • firmware/esp32_ds18b20/
    Sketch de referência para integração física.
  • evidence/
    Logs e capturas dos testes e da demonstração.
Para explicar a lógica, abra readings.py. Para acompanhar o caminho completo, comece pelo simulador e siga até monitor.py e storage.py.
Fala sugerida: “O código está separado por responsabilidade. A regra de alerta fica em readings.py; monitor.py recebe mensagens e storage.py persiste os dados. Os testes cobrem esses comportamentos.”
MediSUS · demonstração06 / 08

05 · execução no VS Code

Mostre o fluxo acontecendo

Abra o projeto no VS Code, inicie o Docker Desktop e use o terminal integrado na pasta do repositório.

1 · Inicie o broker e o monitor

docker compose up -d --build mosquitto monitor

2 · Publique as leituras sintéticas

docker compose --profile demo run --rm simulator

3 · Mostre o log e o alerta

docker compose logs --no-color monitor

4 · Consulte o SQLite, se houver tempo

docker compose exec monitor python -c "import sqlite3; c=sqlite3.connect('/data/readings.sqlite3'); [print(r) for r in c.execute('SELECT temperature_c, alert FROM readings ORDER BY id')]"

Para encerrar sem apagar os dados: docker compose down.

Fala sugerida: “Primeiro subo o broker e o monitor. Depois executo o simulador. Por fim, mostro o log para verificar as leituras e o alerta; a consulta opcional confirma a persistência.”

O teste comprova

O software recebe os valores do simulador, aplica a regra configurada e registra a classificação.

O teste não comprova

Uma condição clínica, a segurança de um produto ou o funcionamento de um sensor físico.

Evidências disponíveis no projeto: evidence/prints/, evidence/logs/ e evidence/EVIDENCIAS.md.

Fala sugerida: “No cenário sintético, 8,3 graus ficou acima do limite demonstrativo e foi registrado como alerta. Os 12 testes automatizados passaram. Isso valida o comportamento do software testado, não um uso clínico.”
